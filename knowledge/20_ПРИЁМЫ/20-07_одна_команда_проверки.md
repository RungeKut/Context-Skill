# Одна команда проверки проекта

## Что происходит
В P-03 есть единый скрипт: подряд запускает четыре проверочных спайка,
симулятор, проверку векторов и тесты реализации на целевом языке, печатает
список проваленных и возвращает ненулевой код при провале. Ключ `--full`
добавляет тяжёлые прогоны. В P-02 команды две: `npm run check` (инварианты
файлов: кодировки, концы строк) и `npm test` (модульные и сквозные тесты).
Единой команды нет.

## Почему
Агент и человек запускают проверку по-разному и проверяют разное. Одна
команда с кодом возврата не оставляет места для «забыл прогнать» и
сообщает о результате за один вызов, без долгого чтения логов.

## Как правильно
* Одна команда в корне проекта, перечисленная в корневом файле
  ([10-01](../10_ДОКУМЕНТЫ/10-01_корневой_файл_до_2кб.md)).
* Быстрый набор по умолчанию, тяжёлый — флагом.
* Печатает, что запускает, и в конце — список проваленных; код возврата
  ненулевой при любом провале.
* Подробный вывод — в файл, в контекст агента — хвост
  ([20-04](20-04_протокол_compact.md) о цене контекста).
* Команда включает и сверку с эталоном
  ([20-06](20-06_эталон_на_скриптовом_языке_и_векторы.md)), если он есть.

## Как неправильно
Три отдельные команды, которые надо помнить; тесты без кода возврата;
печать всего вывода в контекст.

## Чем подтверждено
P-03: скрипт существует, прогоны 2026-10 записаны в документах проекта. P-02:
наличие двух команд проверено по `package.json`.
