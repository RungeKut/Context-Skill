# git add -A до .gitignore

## Что происходит

В новом репозитории выполнено `git add -A`, `.gitignore` ещё не было. В
коммит попал каталог сборки `target/` — сотни файлов.

## Почему

`git add -A` добавляет всё, что не игнорируется; игнорировать было нечего.

## Как правильно

Сначала `.gitignore` (каталог сборки, кэши, локальные файлы), потом
`git add`. Перед коммитом: `git status --short | wc -l` и взгляд на список.
Если коммит ещё не отправлен:

```bash
git rm -r --cached target
git add .gitignore
git commit --amend --no-edit
```

Уже отправленный коммит так не правится: нужна отдельная правка истории по
решению владельца.

## Как неправильно

Коммитить «потом уберём» и пушить: в истории остаётся мусор. Править
amend'ом коммит, который уже в удалённом репозитории.
