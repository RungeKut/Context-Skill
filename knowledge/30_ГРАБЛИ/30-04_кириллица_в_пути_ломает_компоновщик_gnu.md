# Кириллица в пути и компоновщик GNU

## Что происходит

Сборка проекта, лежащего в папке с кириллицей, на этапе компоновки:

```
cannot find <каталог артефактов>\rustc<…>\symbols.o
```

Промежуточный файл компилятор создал, компоновщик его не нашёл.

## Почему

Компоновщик GNU (gcc из PATH) не читает пути с кириллицей: файл есть, но
открыть его по такому пути утилита не может. Механизм глубже не выяснялся.
Тот же симптом у binutils другого набора: MCU-Kit, запись 30-06.

## Как правильно

Вынести каталог артефактов в ASCII-путь в `.cargo/config.toml` проекта:

```toml
[build]
target-dir = "C:/build-cache/app"
```

Каталог проекта переименовывать не требуется.

## Как неправильно

Лечить «cannot find» очисткой кэша или переустановкой toolchain: файл
существует, дело в пути. Переносить исходники ради одной сборки.

## Чем подтверждено

P-03, 2026-10-19: сборка с `target-dir` по умолчанию — ошибка выше; с
`target-dir` в ASCII-каталоге — успешна.
