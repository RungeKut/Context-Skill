# description > 1024 и sed -i

**Устарело (2026-10-28):** description — соседний скилл skill-skill, запись
30-06; `sed -i` и `.bat` — [30-10](30-10_sed_i_в_git_bash_срезает_cr_у_bat.md). Ниже — текст на 2026-10-19.

## Что происходит

1. Лимит `description` в `SKILL.md` — 1024 знака. У Context-Skill v0.1 было
   1205 (замерено): opencode не выдаёт ошибки, скилл просто отсутствует в
   списке. Тот же приём «молчаливая потеря» — у `description` с `: ` без
   кавычек (MCU-Skill, 2026-10-02).
2. **Не проверено.** `sed -i` в Git Bash на `.bat` срезает `CR` в конце
   строк; файл остаётся читаемым глазами, но cmd разбирает его иначе.

## Почему

Загрузчик отбрасывает скилл с длинным описанием без сообщения. Про `sed`
причина предположительно в текстовом режиме Git Bash.

## Как правильно

Мерить длину после каждой правки (`check_docs.py` проверяет frontmatter
скилла). Для `.bat` править редактором или Python с `newline=""`,
затем смотреть `file x.bat` на CRLF.

## Как неправильно

Дописывать триггеры в `description` без счёта знаков. Править `.bat`
через `sed -i`.
