# Установка и окружение

## Подключение агентов

Все агенты читают **один и тот же git-репозиторий**:

```
Context-Kit\                         ← единственный источник
   ├── skill\SKILL.md
   ├── knowledge\  tools\
   ↑
   ├── ~\.claude\skills\context       junction  (Claude Code)
   ├── ~\.kimi-code\skills\context    junction  (Kimi Code)
   └── ~\.config\opencode\skills\context   junction  (opencode)
```

Цель junction — `<корень>\skill`, не корень репозитория: opencode требует
`SKILL.md` прямо в каталоге скилла, а junction на корень протащил бы в
агента весь репозиторий вместе с `.git`. Junction создаётся без прав
администратора:

```powershell
cmd /c mklink /J "$env:USERPROFILE\.config\opencode\skills\context" `
    "<корень набора>\skill"
```

`tools/setup.ps1` делает junction'ы для агентов и Kimi Code; для
opencode — отдельная команда выше. Копия набора вместо junction хуже:
правка одного агента не видна другому, расхождение всплывает через месяцы.
На другую машину правка попадает только через `git push` и `git pull`.

## Проверка junction

Пустой `Get-ChildItem -Recurse` по junction в PowerShell 5.1 не означает
поломку; проверять точечно:

```powershell
Test-Path "$env:USERPROFILE\.config\opencode\skills\context\SKILL.md"
```

## Требования opencode к SKILL.md

`name` — строчная латиница с дефисами, совпадает с именем каталога;
`description` — 1–1024 знака (30-09); при `: ` внутри — в кавычках. Нарушение
молчаливо: скилл просто не появляется в списке. После установки
перезапустить агента — скиллы перечисляются при старте.
