# Работа с репозиторием

## Порядок

```bash
git pull --rebase                  # в начале работы
# ... правка ...
git diff                           # прочитать глазами
python tools/check_docs.py         # шапки, INDEX, стоп-слова, автор
git add <файлы> && git commit -m "что и почему" && git push
```

Push отклонён — `git pull --rebase`, затем проверку заново и перечитать
слитое: git сливает текст, а не смысл. **Один шаг — один коммит.**
Исправление неотправленного коммита — amend; отправленного — новый коммит.

## Обезличивание

Репозиторий публичный. Не попадают: названия проектов, изделий,
репозиториев, серверов, пути и учётные записи, имена людей; источник
записи — метка `P-nn`. Хук `commit-msg` и `check_docs.py` проверяют по
`tools/stoplist.txt`; он **локальный**, в `.gitignore`. Новый проект — строка в
стоп-лист до первого коммита. Описание узла, по которому проект узнаётся
без названия, стоп-лист не ловит — за этим `git diff` глазами.

## Автор коммитов клона

```bash
git config user.name  "<публичное имя>"
git config user.email "<публичный адрес>"
```

Иначе git подставит глобальные настройки машины, и рабочее имя уйдёт в
публичную историю. Стоп-лист этого не ловит; `check_docs.py` требует автора
на уровне клона.

## строка соавторства

Если агент создаёт коммит, в конце сообщения добавляется строка
`строка соавторства: <модель> <noreply-адрес>` — адрес только служебный,
почту владельца в сообщения не вносить. Текст проходит тот же стоп-лист.
