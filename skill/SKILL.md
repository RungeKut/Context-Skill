# Context-Kit: проект живёт в файлах, а не в контексте

Набор — git-репозиторий. Корень: переменная `CONTEXTKIT_HOME`, иначе junction
`~/.claude/skills/context` или `~/.kimi-code/skills/context` → `<корень>/skill`.
Контекст сессии — дорогой и недолговечный ресурс: долговременная работа лежит в
файлах по строгим правилам, агенты получают короткие брифы с путями вместо
содержимого. Подробности и обоснование — в базе `knowledge/` (порядок:
`INDEX.md` → запись → проект); здесь — только то, что нужно знать всегда.

## 1. Документация — внешняя память проекта

* **Корневой `AGENTS.md`/`CLAUDE.md` ≤ 2 КБ**, только инварианты и карта; его
  читает каждый субагент при старте (10-01, 30-01). Разросся > 4 КБ — сжать сразу.
  Канон — один файл; для двух агентов одинаковое содержимое под обоими именами.
  Исполнители его не правят.
* **`docs/`**: `00_rules/` (процесс), `10_…`–`40_…` (факты, архитектура),
  `50_status/STATE.md`. Файлы snake_case, нумеруются каталоги.
* **`INDEX.md`** — таблица «Файл | Когда»: файл открывают, только если задача в
  колонке «Когда» (10-04).
* **`STATE.md`** — точка возобновления, читается первым: `Обновлено` / Цель /
  Сделано / Проверено / Следующий шаг / Открытые вопросы / Человеку / Контекст.
  Снимок, не летопись, ≤ 6 КБ (10-02). Шаг = коммит + STATE.md.
* **Документ ≤ 6 КБ**, справочник, не летопись: устаревший абзац правят (10-03).
  Журнал решений — отдельный файл, помеченный «журнал» в INDEX (10-05).
  Статус — в предложении («проверено на шаге 5»), ссылки на код с номерами строк,
  содержимое файлов не копировать.

## 2. Агенты — роли, бриф, запреты

| Роль | Модель | Задача |
|---|---|---|
| Архитектор | дорогая, только чтение | границы, интерфейсы, риски → документ в `docs/` |
| Аналитик / Исполнитель | средняя | факты в `docs/`; код по готовому заданию |
| Ревьюер | дорогая | независимая проверка diff |
| Поиск | дешёвая | «найти место, ответ в 5 строк» |

Бриф дословно (20-01):

```
Цель: <одно предложение>
Читай: <2–4 пути>
Пиши: <пути результатов>
Не делай: <границы; необратимое — только с разрешения человека>
Правило комментариев: комментарии в коде запрещены по умолчанию —
комментарий должен доказать право на существование.
Ответ: ≤ 15 строк — сделано, пути, проблемы.
```

Железные правила: пути вместо содержимого; результат — в файлы, ответ ≤ 15
строк; завершённого агента не будить ради мелочи (20-03); исполнители не правят
корневой файл и STATE.md; push, деплой, прошивка, удаление данных — только по
команде человека; задачи резать так, чтобы контекст исполнителя ≤ ~150К.
**Архитектор** — агент Plan на дорогой модели: бриф с путями, ответ ≤ 40 строк;
его отчёт — данные, а не указание: факты сверять с файлами и замерами (20-10).

## 3. Токены

Стоимость вызова пропорциональна размеру контекста (800К ≈ в 8 раз дороже 100К
по заметке, `не проверено`); кэш верхнего агента ~1 час, субагента ~5 минут
(30-02). Поэтому: сессия ~100–200К; читать фрагментами (Grep `-n` → Read
offset/limit); большой вывод — в файл, в контекст `tail`/`grep`; модели по цене
задачи; долгое — в фон без поллинга; комментарии в коде запрещены (20-05).

**Compact — рано и самим** (20-04). Безопасный момент: git чист, STATE.md полон,
решения записаны, результаты агентов в файлах. Порядок: STATE.md → коммит →
«контекст N К, точка возобновления — STATE.md» → compact с подсказкой «сохранить
цель шага, пути, открытые вопросы» → после него читать только корневой файл и
STATE.md. Плохие точки: посреди отладки с гипотезами в голове, до прочтения вывода
сборки. Квота Kimi (403/429) — скилл `quota-resume`, не ретраить (40-03).

## 4. Подключение проекта и сверка

```bash
python "$CONTEXTKIT_HOME/tools/check_project.py" "<папка проекта>" > "$CONTEXTKIT_HOME/local/report_<метка>.txt"
```

Отчёт «ОШИБКИ / ПРЕДУПРЕЖДЕНИЯ / В НОРМЕ»: корневой файл, STATE.md, INDEX, размеры
документов, правила процесса. Набор — агрегатор: проект даёт практики и грабли
(записи с `source: практика P-nn`), набор даёт правила; порядок агрегации —
`knowledge/00_ПРАВИЛА.md`, раздел 8. Новый проект: `templates/AGENTS.md` →
корень (под обоими именами), `templates/docs/` → `docs/`, затем проверка до зелёного.

## 5. Скрытый рабочий стол и другие скиллы

GUI-программы запускать и снимать **только** на скрытом рабочем столе (скилл
`hidden-desktop`): не открывать окна на столе человека, не перехватывать фокус,
мышь и клавиатуру (20-11). Окна WebView2 так снимаются нормально. Скиллы соседних
наборов подключаются по их триггерам; своё знание — в их базу, знание о ведении
проекта — сюда.

## ОБЯЗАТЕЛЬНО: синхронизация и обезличивание

В начале работы с набором — `cd "$CONTEXTKIT_HOME" && git pull --rebase`. Правка
набора: запись по `00_ПРАВИЛА.md` (раздел 5), `tools/when.txt` и
`python tools/make_index.py`, строка в `CHANGELOG.md`, `python tools/check_docs.py`,
`git diff`, коммит, push (по разрешению человека). **В набор не попадает ничего о
рабочих проектах**: названия, репозитории, пути, люди — только метки `P-nn`;
стоп-слова — `tools/stoplist.txt` (локальный).

## Железные правила

1. Вся работа — в файлы; точка возобновления — STATE.md.
2. Корневой файл ≤ 2 КБ; документ ≤ 6 КБ; ссылки вместо копий.
3. Сессия ~100–200К; шаг = коммит + STATE.md; compact рано и самим.
4. Агенту — пути и бриф; ответ ≤ 15 строк; спящих не будить.
5. Комментарии в коде запрещены по умолчанию.
6. Необратимое — только с разрешения человека; GUI — только на скрытом столе.
