# Context-Kit: проект живёт в файлах, а не в контексте

Дистилляция правил из `docs/00_rules/` проекта ***_*** и
заметки «По поводу токенов». Идея одна: контекст сессии — дорогой и
недолговечный ресурс, поэтому вся долговременная работа ложится в файлы по
строгим правилам, а агенты получают короткие брифы с путями вместо
содержимого. Набор: `<корень>/skill/SKILL.md` (этот файл) и
`<корень>/templates/` — заготовки для развёртывания в новом проекте.

## 1. Документация — внешняя память проекта

### Корневой файл (AGENTS.md / CLAUDE.md): ≤ 2 КБ

- Его читает каждый субагент при старте: субагент стартует в рабочем каталоге
  родителя и корневой файл прочтёт всегда, сказать ему «не читай» нельзя.
- Содержимое: 2–3 предложения о проекте; **инварианты** — «оставь только ту
  информацию, отсутствие которой сломает проект»; карта docs/ (пути);
  5–7 правил процесса; команды сборки/проверки. Всё подробное — по ссылкам.
- Разросся до > 4 КБ — сжать немедленно. Исполнители этот файл не правят —
  только верхний агент, после проверки результатов.
- Канон — один файл. Если в проекте работают и Claude, и Kimi Code —
  одинаковое содержимое под обоими именами (CLAUDE.md и AGENTS.md).

### Структура docs/ — нумерация десятками, от правил к состоянию

| Каталог | Что лежит |
|---|---|
| `00_rules/` | правила процесса: `token-economy.md`, `agents.md`, `compact.md`, `code-style.md`, `git.md` |
| `10_…`, `20_…`, `30_…`, `40_…` | факты и архитектура проекта — набор разделов свой (железо, архитектура, легаси, генерированное), нумерация задаёт порядок чтения |
| `50_status/` | живое состояние: `STATE.md`, отчёты ревью |

Имена файлов — snake_case, номер только у каталога. Разделы подбираются под
проект, их число — любое.

### INDEX.md — маршрутизация, не оглавление

Таблица «Файл | Когда». Железное правило: открывать файл, только если задача
попала в колонку «Когда» — это защита от лишнего чтения.

### STATE.md — точка возобновления сессии

- Читается первым в начале сессии, до любой работы. Шапка: `Обновлено: <дата>`.
- Разделы: `Цель` / `Сделано` / `Проверено` / `Следующий шаг` (конкретно:
  файл, команда) / `Открытые вопросы` / `Человеку` (что должен проверить или
  решить человек) / `Контекст` (id субагентов, пути scratchpad, ссылки).
- Обновляется после каждого шага. **Один шаг — один коммит (+ push).**
- Всё, что не записано в STATE.md, после компакта считается потерянным.

### Формат документа

- ≤ 6 КБ, иначе делить. Справочник, не летопись: устаревший абзац правим, а
  не дописываем снизу.
- Скелет: `# Тема` → `Источник: <путь/дата>` → разделы `##` с таблицами и
  короткими абзацами.
- Ссылки на код — с номерами строк: `UartInterface.cpp:65-159`. Между
  документами — относительные markdown-ссылки.
- Содержимое файлов в файлы не копировать — только ссылка на путь.
- Статус встраивается в предложение: «проверено на шаге 5», «(по макету, не
  подтверждено)». Отдельного поля «Статус» нет.
- Генерируемые документы помечаются: «править источник и перегенерировать, а
  не этот файл».

## 2. Агенты — роли, бриф, запреты

### Роли (модель — по цене задачи)

| Роль | Модель | Задача |
|---|---|---|
| Архитектор | дорогая | границы модулей, интерфейсы, риски; результат — документ в `docs/20_*/` |
| Аналитик | средняя | выписать факты в `docs/` (источник → документ) |
| Исполнитель | средняя | код по готовому заданию из `docs/`, сборка |
| Ревьюер | дорогая | независимая проверка diff |
| Поиск | дешёвая | «найти место в дереве, ответ в 5 строк» |

В Kimi Code роли примерно соответствуют типам субагентов: планировщик
(architect), исполнитель (coder), поиск (explore), ревьюер (reviewer); модель
выбирается параметром `model`. Промпт запускает модель по вектору и только
по нему: короткий бриф с узкой целью работает лучше длинного сочинения, а
разные промпты на одну задачу (кодер + ревьюер) находят косяки друг у друга.

### Бриф субагенту (дословно)

```
Цель: <одно предложение>
Читай: <2–4 пути из docs/ и исходников>
Пиши: <пути результатов>
Не делай: <границы; необратимые действия — только с разрешения человека>
Правило комментариев: комментарии в коде запрещены по умолчанию —
комментарий должен доказать право на существование.
Ответ: ≤ 15 строк — сделано, пути, проблемы.
```

### Железные правила агентов

1. **Пути вместо содержимого.** Не пересказывать агенту содержимое файлов —
   давать пути.
2. **Результат — в файлы.** «Результаты субагентов уже сохранены в файлы»:
   агент возвращает пути и ≤ 15 строк, остальное лежит в файлах.
3. **Не будить завершённого агента** ради правки на 5 строк — пересчёт его
   контекста дороже новой маленькой задачи. Мелочь делает верхний агент или
   новый короткий субагент.
4. **Исполнители не правят** корневой AGENTS.md/CLAUDE.md и STATE.md —
   обновляет верхний агент после проверки результатов.
5. **Агенты не делают необратимого без разрешения**: push, деплой, прошивка,
   удаление данных — только по команде человека.
6. **Задачи нарезать так**, чтобы контекст исполнителя не взрывался
   (≤ ~150К); пачки задач — заранее продуманные, а не «сделай всё».

## 3. Токены — цена вызова пропорциональна контексту

### Почему это главное правило

- Стоимость каждого вызова инструмента пропорциональна размеру контекста:
  работа на сессии 800К примерно **в 8 раз дороже** той же на 100К.
- Кэш верхнего агента живёт ~1 час между запросами, кэш субагента — ~5
  минут. Промах кэша на большом контексте = платить за каждый токен заново.
- Слепые ретраи, поллинг фоновых задач, «проверить, не закончилось ли» —
  жгут квоту пустыми вызовами.
- Вывод: долгоживущие сессии-«паровозы» запрещены. Шаг = атомарный кусок =
  коммит + обновление STATE.md.

### Приёмы

1. **Лимиты:** верхняя сессия ~100–200К, исполнитель ≤ ~150К. Разрослось —
   compact (протокол ниже).
2. **Читать не целиком:** Grep с `-n`, затем Read с offset/limit;
   прочитанное не перечитывать.
3. **Большой вывод** (сборка, тесты, логи) — в файл scratchpad; в контекст —
   только `tail` / `grep`.
4. **Модели по цене задачи:** дешёвые — на механику и поиск, дорогие — на
   архитектуру и ревью.
5. **Долгое — в фон**, без поллинга: кэш не греть пустыми вызовами.
6. **Ответ субагента ≤ 15 строк**, остальное — файлы.
7. **Комментарии в коде запрещены по умолчанию.** Субагенты пишут их «для
   себя», они устаревают и превращаются во вторую кодовую базу, которую
   следующие агенты почему-то считают приоритетнее самого кода. Код и есть
   лучшая спецификация. Бриф дословно — см. шаблон выше.
8. **Корневой файл ≤ 2 КБ** — его читает каждый субагент на старте.
9. **Квота Kimi Code** (403 «usage limit», 429) — см. скилл `quota-resume`:
   не ретраить, один будильник на время сброса.

### Протокол compact — сжимать рано и самим

Сжатие на 200К дешевле автокомпакта на пределе, и оно безопасно, если вся
работа лежит в файлах.

**Безопасный момент (все условия):** git чист (шаг закоммичен); STATE.md
полон (цель/сделано/следующий шаг/вопросы/id агентов); нет незаписанных
решений; результаты субагентов сохранены в файлы.

- **Хорошие точки:** переход дизайн → реализация; после модуля с зелёной
  сборкой; после ревью; контекст > 200К или «вязкость» (путаница в именах,
  повторные вопросы).
- **Плохие точки:** посреди отладки с гипотезами только в голове (сначала
  раздел «Гипотезы» в STATE.md); пока не прочитан вывод сборки/тестов; пока
  решение не зафиксировано в документе.
- **Порядок:** обновить STATE.md → коммит → сообщить «контекст N К, точка
  возобновления — STATE.md» → compact с подсказкой «сохранить цель шага,
  пути изменённых файлов, открытые вопросы; вывод инструментов отбросить» →
  после компакта читать только корневой файл и STATE.md.
- Субагентов не сжимать, а закрывать. Верхний агент может жить в компактах
  бесконечно, пока вся работа в файлах: компакт очищает ~90% мусора
  (вызовы инструментов, вывод команд), оставляя конспект главного.

## Развёртывание в новом проекте

1. Скопировать `templates/AGENTS.md` в корень проекта (под имена `AGENTS.md`
   и, если нужен Claude, `CLAUDE.md` — содержимое одинаковое).
2. Скопировать `templates/docs/` в `docs/` проекта.
3. Заполнить: инварианты, карту документации, команды сборки, разделы
   `10_…/20_…` под проект.
4. Дальше проект живёт по правилам: STATE.md после каждого шага, документы
   ≤ 6 КБ, компакт рано, агенты по брифу.

## Сводка — железные правила

1. Вся работа — в файлы; точка возобновления — STATE.md.
2. Корневой файл ≤ 2 КБ; документ ≤ 6 КБ; ссылки вместо копий содержимого.
3. Сессия ~100–200К; шаг = коммит + STATE.md; compact рано и самим.
4. Агенту — пути и бриф; ответ ≤ 15 строк; спящих не будить.
5. Комментарии в коде запрещены по умолчанию.
6. Необратимые действия — только с разрешения человека.
